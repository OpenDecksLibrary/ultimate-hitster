# Contributing

Open an issue before proposing large changes. For track corrections or new editions, include the edition, card number, proposed artist/title/year, and a verifiable source. Flag uncertainty and alternate recordings instead of guessing.

For code changes, use a branch and a pull request. Keep changes focused, include tests for validation and stable identifiers when applicable, and describe the Anki versions and platforms tested.

Do not commit credentials, private Anki collections, generated packages or audio files. Keep attribution and source provenance with contributed data. Review licensing and source permissions before adding third-party material.
